## What didn't work / gotchas (NEW this session; prior handoffs' still apply)

- **Lavish viewer sandbox blocks fetch()**: the artifact iframe is sandboxed WITHOUT `allow-same-origin` (opaque origin) and the express server sends NO CORS headers, so `fetch('fleet.json')` fails silently even though the URL itself is 200 (artifact served under `/artifact/<session-id>/...`). Result: empty page skeleton (captain read it as "only a nav pane"). **Fix pattern: load data as a classic `<script src="fleet-data.js">` (subresource loads bypass CORS) and refresh via dynamically inserted script tag with `?t=` cache-buster.** iframes of sibling HTML files work fine (subresource, not fetch).
- **fm-procevent-lavish adapter has no `--agent-reply`** — respond by editing the artifact (Lavish live-reloads it) + chat; after handling each result: `bin/fm-procevent.sh handled <source-id> <seq>` then RE-ARM with `bin/fm-procevent-lavish.sh arm <artifact>` (a feedback capture retires the poll; without re-arm there is no next wake).
- **Dashboard auto-refresh vs unsent choices**: re-render on new data would wipe the captain's un-queued radio picks (the exact loss mode from the belief-loop incident). Implemented: skip re-render when `#fd-decisions` has checked inputs/disabled buttons; show a "new data — refresh" chip instead. Preserve this in any shell rewrite.
- **zsh eats words starting with `=`** (`echo =====` → `==== not found`); don't use `=`-prefixed separator strings in compound commands.
- **529 Overloaded on /compact** is transient server-side; not worth retrying for a teardown-bound worker (compaction re-reads the whole context — real quota).
- **Repo updated under a running session**: new skills/protocols appeared mid-conversation (ack-required drains). When drain output shows `WAKE_ACK_REQUIRED`, run the printed `--ack-through`/`--recovery-generation` command after handling or wakes re-announce.
